# PR 템플릿 (한국어)

한국 프로젝트에 사용한다. 제목과 본문을 한국어로 작성한다.

## 제목

- 50~70자 안팎, 마침표 없이 쓴다.
- 저장소에 커밋 컨벤션이 있으면 맞춘다. 예: `feat: 프롬프트 500자 길이 제한 추가`
- "무엇을"보다 "왜"가 드러나게 쓴다.

## 본문

```markdown
## 요약

<이 PR이 무엇을 왜 하는지 1~3문장.>

## 변경 사항

- <주요 변경 1>
- <주요 변경 2>

## 배경 / 목적

<이 변경이 필요한 이유. 관련 이슈나 논의가 있으면 링크.>

Closes #<이슈 번호>

## 테스트 방법

1. <재현 또는 확인 절차>
2. <기대 결과>

## 체크리스트

- [ ] 테스트를 추가하거나 수정했다
- [ ] 로컬에서 lint, 테스트, 빌드가 통과한다
- [ ] 필요한 문서를 갱신했다
- [ ] 비밀 정보나 무관한 변경이 포함되지 않았다

## 스크린샷 / 참고

<UI 변경은 전/후 화면. 없으면 "해당 없음". 호환성 깨짐이나 후속 작업이 있으면 여기에 적는다.>
```

## 규칙

- 섹션은 모두 유지하고, 해당 없는 섹션은 "해당 없음"으로 둔다.
- 관련 이슈가 없으면 `Closes #` 줄을 지운다.
- 실제로 확인한 항목만 체크한다.
